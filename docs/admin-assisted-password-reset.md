# إعادة تعيين كلمة المرور عبر السوبر أدمن

هذا التنفيذ يعتمد على الاسترجاع عبر السوبر أدمن، وفق الاختيار المعتمد. لا يرسل SMS أو WhatsApp أو OTP، ولا يضيف أرقام استرجاع غير موثقة. لا يسترجع حساب السوبر أدمن نفسه.

## الاستخدام

1. يدخل السوبر أدمن إلى `/admin/users`.
2. يختار «إعادة تعيين كلمة المرور» بجانب حساب أدمن أو موظف نشط.
3. يتحقق من هوية صاحب الحساب عبر وسيلة موثوقة قبل إجراء العملية.
4. يدخل كلمة مرور السوبر أدمن الحالية وكلمة مؤقتة قوية وتأكيدها، ويؤكد العملية.
5. يسلّم الكلمة المؤقتة لصاحب الحساب عبر وسيلة خاصة موثوقة. الموقع لا يرسلها تلقائيًا، ولا يحتفظ بنسخة قابلة للقراءة منها.
6. يدخل صاحب الحساب من `/admin/login` خلال 24 ساعة؛ ينتقل إلى `/admin/change-password`، ويعيد إدخال الكلمة المؤقتة ويحدد كلمة جديدة مختلفة.
7. بعد الحفظ تُلغى جميع الجلسات، ويجب الدخول مجددًا بالكلمة الجديدة.

صفحة `/admin/forgot-password` تشرح هذا المسار فقط ولا تطلب رقم هاتف ولا تكشف وجود حسابات. انتهاء الكلمة المؤقتة يستدعي إعادة تعيين جديدة من السوبر أدمن. إغلاق صفحة تغيير الكلمة يسمح بإكمالها بالدخول بالكلمة المؤقتة خلال صلاحيتها؛ الجلسة المقيدة مدتها القصوى 10 دقائق ولا تدعم «تذكّرني».

## التوافق والأمان

- إعادة استخدام scrypt وسياسة كلمات المرور الحالية: 8–128 حرفًا، حروف وأرقام ورمز.
- إعادة استخدام الجلسات، Secure/HttpOnly/SameSite=Lax، CSRF، Origin، وحدود المحاولات في D1.
- لا يتم كشف كلمة المرور أو تجزئتها في API إدارة المستخدمين.
- `requireApi` يحجب APIs الإدارة والرفع عن الحساب الملزم بالتغيير، و`requirePage` يحوله إلى صفحة التغيير. يسمح فقط بتغيير كلمة المرور أو تسجيل الخروج، وقراءة حالة المصادقة اللازمة للصفحة.
- لا يسمح بإعادة تعيين حساب سوبر أدمن أو الحساب الحالي بهذا المسار، ولا يسمح بإعادة تعيين حساب معطّل.
- إعادة التعيين والتغيير وإلغاء الجلسات وتسجيل أحداث الأمان تُنفّذ ذريًا في D1، مع إعادة فحص حالة الحساب والتجزئة والجلسة. أُعيد استخدام حارس المعاملات SQLite الموجود لضمان التراجع الكامل عند التعارض.
- لا تتغير الأدوار أو الصلاحيات أو حالة الحساب؛ الحسابات الحالية تحتفظ بكلماتها عند النشر.
- الأحداث `admin_forced_password_reset` و`password_reset_completed` تحفظ الفاعل والحساب المستهدف والتوقيت دون كلمات مرور أو رموز.
- جميع الحالات اللازمة محفوظة في D1 وليست في ذاكرة Worker؛ النشر لا يفقد حالة وجوب التغيير.

## Migration

`drizzle/0005_mysterious_blue_marvel.sql` يضيف إلى `admin_users` فقط:

- `force_password_change`: افتراضيًا 0 للحسابات الحالية.
- `temporary_password_expires`: فارغ للحسابات الحالية.

لا يحذف جداول أو حسابات ولا يعيد تهيئة البيانات. احتفظ بنسخة قاعدة البيانات قبل تطبيق الترحيلات على استضافة أخرى، وطبّق فقط الترحيلات غير المنفذة بالترتيب؛ لا تعد تشغيل ملفات الإنشاء فوق قاعدة موجودة.

## الإعدادات الخارجية

لا يتطلب هذا المسار شركة SMS أو مفاتيح أو Secrets إضافية. إعدادات WhatsApp إشعارات الطلبات الحالية مستقلة وغير معدلة.

## الاختبار

محليًا: `pnpm install --frozen-lockfile` ثم `node tests/admin-flow.mjs` و`pnpm exec tsc --noEmit`. اختبارات التدفق تستخدم SQLite مؤقتًا ولا تتصل بقاعدة الإنتاج. لتشغيل الموقع اتبع تعليمات المشروع الحالية وطبّق الترحيلات على D1 محلي منفصل.

بعد النشر على Cloudflare: طبّق الترحيل الإضافي مع حفظ بياناتك؛ أنشئ حساب موظف مخصص للاختبار من السوبر أدمن، وجرّب الخطوات أعلاه في متصفح منفصل. تحقق أن جلسة الموظف السابقة تتوقف، وأن الكلمة المؤقتة لا تفتح أقسام الإدارة أو APIs، وأن الدخول يعود بعد التغيير دون اختلاف في الصلاحيات. لا تختبر إعادة التعيين على حساب عمل حقيقي بدون موافقة صاحبه.

تغطي الاختبارات المعزولة النجاح، رفض غير السوبر أدمن، كلمة السوبر أدمن الخاطئة، اختلاف التأكيد، منع تغيير حساب السوبر أدمن، إبطال الجلسات و«تذكّرني»، حجب الصفحات والرفع وAPIs، CSRF، إعادة استخدام الكلمة المؤقتة، تكرار إعادة التعيين، انتهاء الصلاحية، والحساب المعطّل، مع مقارنة بيانات التجارة قبل/بعد. لم تُرسل رسائل فعلية، ولم تُغيّر كلمات مرور حسابات الإنتاج لأجل الاختبار.
