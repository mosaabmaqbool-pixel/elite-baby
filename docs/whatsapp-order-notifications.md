# إشعارات الطلبات عبر WhatsApp

## ما تم تنفيذه

بعد نجاح معاملة حفظ الطلب والمخزون في قاعدة البيانات، يرسل السيرفر قالب WhatsApp عبر Cloud API بالخلفية باستخدام `waitUntil` الخاص بـCloudflare Workers. لا يفتح الزبون WhatsApp ولا يضغط زر إرسال.

لا توجد تغييرات في الجداول، أو واجهة المتجر، أو الدفع، أو لوحة الإدارة. لا تُرسل رسائل من معاينة السعر أو من إعادة نفس طلب الحفظ باستخدام `requestId` نفسه. الإشعارات تشمل الطلبات التجريبية أيضًا، مع علامة واضحة «طلب تجريبي» بجانب رقم الطلب؛ لا تتحول الطلبات التجريبية إلى طلبات فعلية.

فشل WhatsApp لا يلغي الطلب ولا يحذف بياناته ولا يعيد المخزون. لا توجد إعادة إرسال آلية في هذه النسخة؛ خطأ مهلة الاتصال قد يعني أن Meta استلمت الرسالة قبل انتهاء الاتصال. قبول Meta للرسالة لا يثبت وصولها إلى الهاتف؛ تتبع التسليم عبر Webhooks ليس ضمن هذا التنفيذ.

## تجهيز حساب Meta

1. جهّز WhatsApp Business Platform / Cloud API، ورقم إرسال مسجّلًا فيه. تطبيق WhatsApp Business وحده لا يوفّر بيانات الربط المطلوبة.
2. استخدم رقم استقبال مختلفًا عن رقم الإرسال، مع رمز البلد. إن كنت تستخدم رقم الإرسال التجريبي لدى Meta، أضف رقم الاستقبال وتحقق منه ضمن مستلمي الاختبار.
3. أنشئ قالبًا عربيًا بمتغيرات مرقمة، بالترتيب أدناه، وانتظر اعتماده. الإشعارات الاستباقية خارج نافذة خدمة العملاء تحتاج قالبًا معتمدًا؛ موافقة القالب وتصنيفه تخضع لـMeta.
4. جهّز Access Token صالحًا وصلاحية `whatsapp_business_messaging` للوصول إلى رقم الإرسال. تجنّب الاعتماد على توكن اختبار قصير العمر في التشغيل الدائم.
5. أدخل الإعدادات التالية في أسرار الاستضافة، وليس في GitHub أو ملفات الواجهة أو المحادثة. في Cloudflare Workers: إعدادات Worker ثم Variables and Secrets. في استضافة Sites الحالية: إعدادات أسرار الموقع. إذا نقلت المشروع، أدخلها من جديد في الاستضافة الجديدة.

| الإعداد | معناه |
| --- | --- |
| `WHATSAPP_ACCESS_TOKEN` | توكن Meta؛ سرّ لا يظهر في الواجهة |
| `WHATSAPP_PHONE_NUMBER_ID` | معرّف رقم الإرسال، وليس رقم الهاتف نفسه |
| `WHATSAPP_ADMIN_NUMBER` | رقم مستلم إشعارات الطلبات، مع رمز البلد |
| `WHATSAPP_TEMPLATE_NAME` | اسم القالب المعتمد كما هو في Meta |
| `WHATSAPP_TEMPLATE_LANGUAGE` | رمز لغة القالب المعتمدة، مثل `ar` |
| `WHATSAPP_API_VERSION` | إصدار Graph API المدعوم لحسابك بصيغة `vNN.N`؛ انسخه من إعدادات/توثيق Meta الحالي |

ملف `.env.example` يذكر أسماء الإعدادات فقط. لا يحتوي بيانات حقيقية. لا تُعدّل رقم التواصل الاجتماعي في المتجر لهذا الربط؛ رقم الإشعارات مستقل.

## قالب الرسالة

أنشئ قالبًا يحتوي نص Body فقط، بدون Header أو Footer أو Buttons، ومتغيرات مرقمة من 1 إلى 11 بهذا الترتيب:

```text
إشعار طلب جديد من متجر MyStore
رقم الطلب: {{1}}
اسم العميل: {{2}}
الهاتف: {{3}}
المنطقة: {{4}}
المدينة والعنوان: {{5}}
المنتجات والتصاميم والكميات والأسعار: {{6}}
مجموع المنتجات: {{7}}
الخصم: {{8}}
التوصيل: {{9}}
الإجمالي النهائي: {{10}}
طريقة الدفع: {{11}}
```

متغير المنتجات يتضمن اسم المنتج، الخيارات/التصميم المختار إن وجد، الكمية، سعر القطعة ومجموع السطر. الأسعار مأخوذة من حساب السيرفر الذي حُفظ به الطلب، وليست قيمًا يرسلها الزبون.

مع الطلبات الطويلة تُقسّم تفاصيل المنتجات إلى عدة رسائل من القالب نفسه، مع رقم الجزء بجانب رقم الطلب. لا تُحذف الخيارات أو المنتجات من التفاصيل. لهذا قد ينتج عن طلب كبير أكثر من رسالة وتكلفة إرسال حسب تسعير Meta.

## التفعيل والتحقق

- عندما تكون الإعدادات غير مكتملة، يحفظ المتجر الطلب ويُسجّل `not_configured` مع أسماء الإعدادات الناقصة؛ لا يرسل شيئًا.
- بعد توفير الإعدادات، أعد نشر الموقع إن كانت الاستضافة تتطلب ذلك لتطبيق الأسرار، ثم أنشئ طلبًا تجريبيًا من المتجر.
- راجع سجل `whatsapp_order_notification_accepted`، ثم تحقق من وصول الرسالة على الهاتف. السجل يتضمن رقم الطلب ومعرّف الرسالة وعدد الأجزاء.
- عند الفشل، راجع `whatsapp_order_notification_failed`: رقم الطلب، سبب الفشل، HTTP status ورمز الخطأ من Meta عند توفره. `cloud_api_rejected` يعني رفض الطلب، و`timeout` انتهاء المهلة، و`network_or_processing_error` خطأ اتصال/معالجة، و`invalid_configuration` إعدادًا غير صالح.
- لا تُسجّل ترويسة Authorization أو بيانات الطلب كاملة أو التوكن. تُنقّح رسائل الأخطاء قبل تسجيلها.
- تأكد من أن القالب معتمد ومطابق للاسم واللغة وعدد المتغيرات، والتوكن صالح، وصلاحيات رقم الإرسال صحيحة.

## الاختبارات

الاختبارات تستخدم قاعدة SQLite مؤقتة، ومحاكاة Cloud API و`waitUntil`. تغطي حفظ الطلب قبل الإرسال، البيانات والتصاميم والأسعار، عدم إرسال إشعار من معاينة السعر أو إعادة الطلب، وفشل الإرسال دون فقد الطلب. لا تستعمل قاعدة الإنتاج ولا تُرسل رسائل حقيقية.

الوصول الحقيقي إلى Meta ووصول الإشعار إلى الهاتف لا يمكن اختباره قبل توفير بيانات الربط وقالب معتمد.
